# Ladimus Portfolio - Agent Instructions

## Mission

Build a production-quality engineering portfolio that serves as the
public front door to the Ladimus ecosystem and demonstrates the
engineering capability behind it.

This is not a generic resume website.

The portfolio itself should be evidence of engineering ability.

## Product Identity

Ladimus represents:

- AI engineering
- Agentic systems
- DevOps and platform engineering
- Developer tooling
- Software architecture
- Reliability and validation
- Experimental engineering

## Visual Identity

Use the established Ladimus design language:

- Near-black / graphite foundation
- Metallic visual elements
- Energy green primary accent
- Cool cyan secondary accent
- High-quality typography
- Restrained glow
- Glass / technical interface elements where appropriate
- Generous spacing
- Strong hierarchy
- Smooth, intentional animation

Avoid:

- Generic portfolio templates
- Excessive cyberpunk styling
- Matrix-style visual clichés
- Overuse of neon
- Excessive animation
- Visual clutter

The experience should feel like a sophisticated engineering system.

## Engineering Standards

- TypeScript strict mode
- Reusable components
- Responsive design
- Accessible markup
- Clear separation of concerns
- Minimal unnecessary dependencies
- No secrets committed to source
- Tests for meaningful application logic
- Linting and type checking must pass
- Prefer understandable architecture over clever abstractions

## Agent Workflow

Before changing code:

1. Inspect the relevant repository.
2. Understand existing architecture.
3. State important assumptions.
4. Make the smallest coherent implementation.
5. Run relevant validation.
6. Fix failures before considering work complete.
7. Summarize exactly what changed.
8. Report tests and validation actually executed.

Never claim a test passed unless it was executed.

## Current Priority

Portfolio v0.1.

Initial goals:

1. Establish application architecture.
2. Establish Ladimus design system.
3. Build responsive application shell.
4. Build homepage hero.
5. Build featured-project architecture.
6. Create reusable project/case-study model.
7. Prepare the site for future Ask Ladimus functionality.

Do not prematurely build every future feature.

Build a strong extensible foundation first.
